# kind는 사용처가 정하는 문자열로 두고 라이브러리는 목록을 갖지 않는다

`ProjectKind`는 `string`이다.
라이브러리는 kind 목록을 갖지 않고 형식만 검사한다. 비교는 완전 일치다.
형식 규칙과 규칙을 어긴 값의 처리는 `docs/format.md`의 "kind"에 있다.

## 이유

- 사용처마다 파일 종류가 다르다. 목록을 라이브러리가 가지면 사용처가 늘 때마다 라이브러리를 고쳐 배포해야 한다.
- kind는 헤더에 평문 ASCII로 있다. 키가 없는 서버도 읽는다. 규칙이 정규식 하나라서 다른 언어 구현도 전체 일치로 검사하면 같은 판정을 한다. 끝 줄바꿈 주의는 `docs/format.md`의 "kind"에 있다.
- kind 길이 상한이 헤더 최대 길이(`MAX_HEADER_BYTES`)를 정한다. `Blob` 입력은 이 앞부분만 읽으면 헤더를 검사할 수 있다.
- 대문자를 받지 않아서 완전 일치 비교에서 대소문자만 다른 kind가 생기지 않는다.

## 버린 대안

- 라이브러리가 고정 목록(열거형)을 갖는다. 위 이유로 버렸다.
- 사용처 접두(`acme.blocks`의 `acme.`)를 강제한다. 라이브러리는 사용처 목록이 없어 접두를 검증할 근거가 없다. README는 겹침을 피하려고 접두를 권하기만 한다.

## 결과

- 사용처 사이의 kind 충돌을 라이브러리가 막지 못한다. 사용처가 겹치지 않는 이름을 고른다.
- kind는 와이어 포맷 값이다. 사용처가 kind 문자열을 바꾸면 이전 kind로 만든 파일은 `kind-mismatch`로 거부된다.
