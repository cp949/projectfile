# 도메인 문서 사용 규칙

이 저장소는 pnpm + Turborepo 모노레포이지만 패키지가 하나인 단일 컨텍스트다. 업무 용어와 결정은 `docs/`에 둔다.

## 탐색 전에 읽을 문서

- `docs/format.md`: 포맷과 검사 규칙. 업무 용어의 기준.
- `docs/adr/`: 작업 영역에 관련된 결정.
- `docs/design/`: 소스의 구조적 설계 결정.

작업 영역에 관련된 ADR이나 설계 문서가 없으면 조용히 진행한다. 없다는 사실을 알리거나 미리 만들자고 제안하지 않는다. 만드는 조건은 `AGENTS.md`의 "장기 설계"를 따른다.

## 파일 구조

```
/
├── docs/
│   ├── format.md
│   ├── adr/
│   └── design/
└── packages/projectfile/
```

## 용어 사용

이슈 제목, 리팩터링 제안, 가설, 테스트 이름에 업무 개념을 쓸 때는 `docs/format.md`가 쓰는 이름을 쓴다.

- 용어는 따로 모은 목록 없이 `docs/format.md`의 절 제목과 규칙 문장에 있다. 예: kind, scramble 키, 키 확인값, asset, 한도.
- 문서가 쓰는 이름을 다른 동의어로 바꾸지 않는다.
- 필요한 개념이 문서에 없으면 새 용어를 만들고 있는지, 문서에 빈 곳이 있는지 판단한다. 빈 곳이면 용어를 정해 어느 문서에 더할지 사용자에게 묻는다.

## ADR 충돌 표시

출력이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 명시한다.

> ADR-0007(...)과 충돌한다. 다시 검토할 만한 이유는 ...
