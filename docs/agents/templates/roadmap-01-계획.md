# 작업 계획

## 착수 커밋

- 작업 브랜치를 만든 시점의 `git rev-parse dev` 전체 40자.
- 작업 브랜치: `<커밋 타입>/<작업 slug>`

## 요구사항

- 사용자 요청을 의미가 달라지지 않게 정리한다.

## 핵심 목표

- 작업이 끝났을 때 달라져 있어야 할 결과를 적는다.

## 범위

- 포함되는 변경 경계를 적는다.

## 비범위

- 하지 않을 일을 적는다.

## 중요한 점

- 여러 RD에 걸친 사용자 결정, 데이터 계약, 주의할 점을 적는다.
- 가정이면 가정이라고 적는다.

## 전체 검증

```bash
pnpm verify
```

## RD 진행 표

| RD                         | 결과       | 상태 | 선행 |
| -------------------------- | ---------- | ---- | ---- |
| [RD-01](./RD-01-결과명.md) | 결과 한 줄 | 대기 | 없음 |

상태: 대기, 진행, 완료, 보류. RD 세부 내용은 RD 파일에만 적는다.

## 변경 이력

- yyyy-MM-dd: RD 추가, 분리, 삭제와 이유를 한 줄로 적는다.
