# qq-workflow

간단한 작업을 계획서 하나와 `dev` 병합 전 리뷰로 처리하는 경량 흐름이다. 계획서를 남기는 목적은 결과물을 리뷰하기 위해서다. RD와 DELTA를 쓰지 않는다.

공통 계약(DELTA 크기, Git, 검증 게이트, 리뷰 기록)은 [`./workflow-shared.md`](./workflow-shared.md)를 따른다.

## 언제 쓰나

진입 규칙은 `AGENTS.md`의 "작업 레인"이 소유한다. 적합한 크기는 DELTA 하나다.

- 계획 단계에서 DELTA 상한을 넘을 것으로 보이면 계획 승인 전에 보고한다.
- 구현 중 상한을 넘으면 멈추고 보고한다. 에이전트가 roadmap-workflow로 바꾸지 않는다.

```text
qq-workflow로 진행: <작업 설명>
qq-workflow 단계-3 진행 (_works/<yyyyMMdd>-<seq>)
```

작업 폴더 인자는 앞부분만 줘도 `_works/` 직속에서 유일하게 매칭되면 그 폴더로 본다. 완료해 `_works/_completed/`로 옮긴 폴더는 전체 경로로 지정한다. 매칭이 없거나 둘 이상이면 후보를 출력하고 정지한다.

## 진행 방식

단계-1의 계획 승인 뒤 단계-4까지 자동 진행한다. 승인은 임시 작업 브랜치 작업과 리뷰 통과 뒤 `dev` 병합까지 포함한다. push와 `main` 병합은 포함하지 않는다.

계획서가 다루지 않는 결정 지점을 만나면 추측하지 않고 멈춰서 묻는다. 단계 진입 가부는 선행 산출물 파일의 존재로 판정한다.

## 작업 폴더

```text
_works/<yyyyMMdd>-<seq>-<한글작업명>/
  _meta.md
  01-계획.md
  IMPL-REVIEW-01.md  IMPL-REVIEW-02.md  ...
```

`_meta.md`:

```markdown
- 레인: qq
- 상태: 진행중 | 완료
```

`01-계획.md` 필수 절. 형식은 `docs/agents/templates/qq-01-계획.md`를 따른다.

1. 착수 커밋: 작업 브랜치를 만든 시점의 `dev` 커밋 전체 40자.
2. 목적: 한 문장.
3. 변경 대상: 예상 파일 경로.
4. 완료 조건: 검증 가능한 문장. 단계-3이 실측 증거와 대조한다.
5. 검증 명령: 복사해 바로 실행할 수 있는 형태.
6. 범위 밖.
7. 참고 지침서: `docs/agents/` 등에서 직접 적용되는 문서. 없으면 `없음`.

판단이 필요했던 지점은 `01-계획.md`의 `## 결정` 절에 주제, 결정, 근거를 append한다.

## 단계-1. 계획

- 작업 폴더, `_meta.md`, `01-계획.md`를 만든다.
- 코드는 변경 대상과 완료 조건을 정할 만큼만 읽는다. 구현 방법과 테스트 내부 구조는 적지 않는다.
- 계획서를 사용자에게 제시하고 승인을 받는다.
- 승인 후 `workflow-shared.md`의 "작업 브랜치"대로 임시 작업 브랜치를 만들고, 착수 커밋을 `01-계획.md`의 `착수 커밋` 절에 적는다.
- 정지: 승인 전에 코드를 고치지 않는다.

## 단계-2. 구현

- 계획서와 참고 지침서를 읽고 구현한다.
- 테스트 작성·정리와 TDD 적용 여부는 [testing.md](./testing.md)를 따른다.
- 작업 브랜치에 필요할 때마다 커밋한다. 리뷰나 검증 통과를 기다리지 않는다.
- 계획서의 검증 명령을 실행한다.
- 마지막에 `workflow-shared.md`의 "테스트 정리"를 한다.
- 정지: 계획과 현재 코드가 충돌하거나 새 사용자 결정이 필요하면 멈추고 보고한다.

## 단계-3. 리뷰

입력: `workflow-shared.md`의 "리뷰 대상 diff"(착수 커밋 기준 변경과 untracked 파일), `01-계획.md`, 참고 지침서.

한 리뷰 파일에 두 부분을 담는다.

1. 완료 조건 대조: 메인 세션이 계획서의 완료 조건을 실측 증거로 `PASS` / `FAIL` 판정한다. 근거는 테스트 제목, 명령과 출력, 파일 경로다.
2. 결함 탐지: `workflow-shared.md`의 "독립 리뷰"로 수행한다.

`FAIL`과 blocker·major는 수정하고 같은 범위를 다시 검증한다. 동작 결함 수정은 RED를 먼저 확인한다. 수정으로 테스트를 더하거나 고쳤으면 `workflow-shared.md`의 "테스트 정리"를 다시 한다.

- 재리뷰는 blocker를 고친 경우에만 1회 한다.
- major와 minor만 고쳤다면 메인 세션이 수정 diff와 검증 명령으로 확인하고 재리뷰하지 않는다.
- 재리뷰 뒤에도 `FAIL`·blocker·major가 남으면 사용자에게 보고한다.

## 단계-4. 병합

- 게이트: `IMPL-REVIEW-*.md`가 없거나 최신 리뷰에 미해결 `FAIL`·blocker·major가 있으면 아무것도 바꾸지 않고 정지한다. 사용자가 리뷰 생략을 명시 지시한 경우만 예외이며 `## 결정`에 적는다.
- 절차:
  1. `workflow-shared.md`의 "검증 게이트" 중 `dev` 병합 직전 검증을 통과시킨다.
  2. "병합"대로 작업 브랜치를 `dev`에 squash 병합하고 작업 브랜치를 삭제한다.
  3. `_meta.md`의 `상태`를 `완료`로 바꾼다.
  4. `workflow-shared.md`의 "작업 폴더 보관"대로 작업 폴더를 `_works/_completed/`로 옮긴다.
- 보고: 결과, 검증, 남은 위험, `dev`의 미푸시 커밋 수. push와 `main` 병합은 지시가 있을 때만 한다.
