# roadmap-workflow

qq-workflow 하나로 끝내기 큰 작업을 독립 완료 결과인 RD로 나누고, RD 안에서 DELTA를 하나씩 계획·구현·리뷰하는 흐름이다. 작업은 임시 작업 브랜치에서 진행하고 마지막에 `dev`로 squash 병합한다. 처음부터 완벽한 계획을 세우지 않는다.

공통 계약(DELTA 크기, Git, 검증 게이트, 리뷰 기록)은 [`./workflow-shared.md`](./workflow-shared.md)를 따른다.

## 핵심 원칙

- 최초 계획에는 핵심 목표, 중요한 점, RD, 예상 DELTA 한 줄만 쓴다.
- 세부 계획은 DELTA를 구현하기 직전에 현재 코드를 보고 세운다.
- 예상 DELTA는 확정이 아니다. 구현 결과를 보고 추가, 삭제, 수정한다.
- DELTA는 하나씩 진행한다. 세부 계획부터 리뷰와 결과 기록까지 끝낸 뒤 다음 DELTA를 고른다.
- RD가 끝나면 RD 전체 변경을 통합 리뷰한다.
- 각 단계는 이전 대화가 아니라 `_works` 문서를 기준으로 독립 실행할 수 있어야 한다.

## 용어와 크기

```text
작업
  └─ 01-계획.md (큰 계획, RD 진행 표)
      ├─ RD-01-<결과명>.md: 독립 완료 결과 하나 → DELTA 2~4개 (최대 8개)
      ├─ RD-02-<결과명>.md
      └─ RD-03-<결과명>.md
```

- `RD-NN`: 독립 완료 조건을 가진 DELTA 묶음이며 통합 리뷰 단위다.
- `DELTA`: RD 안에서 구현·리뷰를 한 번에 끝내는 변경 단위다. DELTA 하나에 커밋 여러 개가 있어도 된다. 번호는 RD마다 `01`부터 시작한다.
- 번호는 참조 ID다. 삭제한 번호를 재사용하지 않는다.
- DELTA 크기는 `workflow-shared.md`의 "DELTA 크기 규칙"을 따른다. 구현 중 상한을 넘을 것으로 보이면 완결 가능한 지점에서 현재 DELTA를 끝내고 나머지를 다음 예상 DELTA로 넘긴다.
- RD 크기: DELTA 2~4개 권장, 최대 8개. 통합 리뷰가 한 번에 다룰 수 있는 크기를 유지하기 위한 상한이다. 9번째가 필요하면 남은 완료 조건과 예상 DELTA를 새 RD 파일로 옮기고 `01-계획.md` 변경 이력에 이유를 적는다.

## 작업 폴더

```text
_works/<yyyyMMdd>-<seq>-<한글작업명>/
  01-계획.md
  RD-01-결과명.md
  RD-02-결과명.md
  RD-01-DELTA-01-작업명.md
  RD-01-DELTA-02-작업명.md
  IMPL-REVIEW-RD-01-DELTA-01-01.md
  RD-REVIEW-RD-01-01.md
  02-작업결과.md
```

- `01-계획.md`: 요구사항, 핵심 목표, 범위, 비범위, 중요한 점, 전체 검증, RD 진행 표, RD 단위 변경 이력.
- `RD-NN-<한글결과명>.md`: 트랙-1에서 RD마다 만든다. 상태, RD 착수 커밋, 결과, 중요한 점, 완료 조건, 예상 DELTA 백로그, 결정, DELTA 단위 변경 이력.
- `RD-NN-DELTA-NN-<한글작업명>.md`: DELTA 착수 시 만든다. 세부 계획과 결과.
- `IMPL-REVIEW-RD-NN-DELTA-NN-NN.md`, `RD-REVIEW-RD-NN-NN.md`: 리뷰 산출물.
- `02-작업결과.md`: 전체 결과 요약.

DELTA 파일을 미리 만들지 않는다. 템플릿은 `docs/agents/templates/`의 `roadmap-*` 파일을 따른다.

## 사용자 결정 경계

roadmap 승인 뒤 자동 진행한다. 다음 경우에만 멈추고 묻는다.

- 작업 범위가 `01-계획.md`의 범위를 넘는다.
- 핵심 목표나 RD 완료 결과의 의미가 바뀐다.
- 공개 API, 파일 포맷(`docs/format.md`), 보안 경계가 바뀐다.
- 새 런타임 의존성이 필요하다.

DELTA 추가·삭제·순서 변경과 RD 분리는 묻지 않고 진행한다. DELTA 변경은 RD 파일, RD 추가·분리는 `01-계획.md`의 변경 이력에 한 줄로 남긴다.

## 트랙-1: roadmap 작성

`01-계획.md`와 RD 파일을 작성한다.

- `01-계획.md`에 핵심 목표, 범위, 비범위, 중요한 점, 전체 검증 명령, RD 진행 표를 적는다.
- 독립 완료 결과 단위로 RD를 나누고 RD 파일마다 결과, 중요한 점, 완료 조건, 예상 DELTA 한 줄 목록을 적는다.
- 코드 읽기는 RD 경계와 중요한 점을 잡는 데까지만 한다. 대상 파일 확정, 구현 방법, 테스트 설계, 코드·테스트 실행은 하지 않는다.
- 사용자에게 제시해 승인을 받는다. 승인은 결과 경계와 전체 범위의 승인이며, 임시 작업 브랜치 작업과 최종 점검 뒤 `dev` 병합을 포함한다. push와 `main` 병합은 포함하지 않는다.
- 정지: 승인 전에 코드를 고치지 않는다.

## 트랙-2: DELTA 사이클

1. 선택: 진행 중인 RD 파일의 예상 DELTA 백로그에서 첫 실행 가능 항목을 고른다. RD가 완료되면 `01-계획.md` 진행 표에서 선행 RD가 모두 완료된 다음 RD로 넘어간다. 첫 DELTA면 `workflow-shared.md`의 "작업 브랜치"대로 임시 작업 브랜치를 만들고 착수 커밋을 `01-계획.md`의 `착수 커밋` 절에 적는다. DELTA 파일의 `DELTA 착수 커밋`에는 그 시점의 `git rev-parse HEAD`를 적는다. RD의 첫 DELTA면 같은 값을 RD 파일의 `RD 착수 커밋`에 적는다.
2. 세부 계획: `RD-NN-DELTA-NN-*.md`를 만들고 `세부 계획` 절을 채운다. 현재 코드를 읽고 필요하면 실행해 확인한다. 직전 DELTA 결과를 반영한다.
3. 구현: 테스트 작성·정리와 TDD 적용 여부는 [testing.md](./testing.md)를 따른다. 작업 브랜치에 필요할 때마다 커밋한다. 세부 계획의 검증 명령을 실행한다.
4. 테스트 정리: `workflow-shared.md`의 "테스트 정리"를 한다. 결과는 DELTA 파일의 `결과` 절에 적는다.
5. 리뷰: 대상은 `workflow-shared.md`의 "리뷰 대상 diff"다. 메인 세션이 완료 조건을 대조하고, `workflow-shared.md`의 "독립 리뷰"로 결함을 탐지한다. `IMPL-REVIEW-RD-NN-DELTA-NN-NN.md`에 기록한다. blocker·major를 수정하고 다시 검증한다. 최대 3라운드. 수정으로 테스트를 더하거나 고쳤으면 테스트 정리를 다시 한다.
6. 결과: DELTA 파일의 `결과` 절을 채운다.
7. 커밋 정리: 리뷰 수정과 결과 기록까지 작업 브랜치에 커밋해 작업 트리를 깨끗하게 만든다. `dev`에는 병합하지 않는다.
8. 계획 갱신: RD 파일에서 해당 DELTA와 충족한 완료 조건을 체크하고 증거(테스트 제목, 명령, DELTA 파일)를 적는다. 드러난 사실을 반영해 다음 예상 DELTA를 추가·수정한다.

3라운드 뒤에도 blocker·major가 남으면 다음 DELTA로 넘어가거나 `dev`에 병합하지 않고 사용자에게 보고한다.

## 트랙-3: RD 통합 리뷰

RD의 완료 조건이 모두 체크되면 RD 전체 변경을 리뷰한다.

- 범위: `git diff <RD 착수 커밋>..HEAD`(작업 브랜치). `dev`에 푸시하지 않은 커밋이 많아도 착수 커밋 기준이므로 이 RD의 변경만 보인다.
- 관점: DELTA 사이 계약 일관성, 공개 API(`src/index.ts`) 경계, `docs/format.md`와 구현의 일치, 중복 구현, 회귀, 과한 구현, RD 완료 조건 충족.
- 메인 세션이 RD 완료 조건을 실측 증거와 재대조하고, 결함 탐지는 `workflow-shared.md`의 "독립 리뷰"로 한다.
- `RD-REVIEW-RD-NN-NN.md`에 기록한다.
- blocker·major 수정은 같은 RD의 새 DELTA로 진행한다. 이미 커밋한 이력은 고치지 않는다. 수정 DELTA도 RD의 DELTA 수에 포함한다. 수정 뒤 수정 범위만 다시 리뷰한다. 최대 3라운드.
- 통과하면 RD 파일과 `01-계획.md` 진행 표의 상태를 `완료`로 바꾼다.

## 트랙-4: 최종 점검과 작업 결과

모든 RD가 완료되면 진행한다.

- `01-계획.md`의 전체 검증 명령을 실행한다.
- `docs/agents/templates/최종-완료-체크리스트.md` 기준으로 점검한다. 작업 폴더에 복사하지 않는다.
- `02-작업결과.md`를 작성한다. RD·DELTA 세부 내용은 파일 링크로 대신한다.
- 작업 전체의 테스트를 대상으로 `workflow-shared.md`의 "테스트 정리"를 한 번 더 한다. DELTA 사이에 같은 위험을 두 번 검증하는 테스트를 통합한다. 결과는 `02-작업결과.md`에 적는다.
- 소스와 테스트의 주석, 테스트 제목을 `docs/agents/writing-styles.md` 기준으로 최종 점검한다.
- `workflow-shared.md`의 "검증 게이트" 중 `dev` 병합 직전 검증을 통과시킨 뒤, "병합"대로 작업 브랜치를 `dev`에 squash 병합하고 작업 브랜치를 삭제한다.
- 병합 뒤 `workflow-shared.md`의 "작업 폴더 보관"대로 작업 폴더를 `_works/_completed/`로 옮긴다.
- 보고: 결과, 검증, 남은 위험, `dev`의 미푸시 커밋 수, 이동 뒤 작업 폴더 경로. push와 `main` 병합은 지시가 있을 때만 한다.
